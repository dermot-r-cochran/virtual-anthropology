# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**The Archipelago**, in `the-archipelago/`: a deterministic, event-sourced virtual civilisation of simulated digital persons across four law-governed islands (Continuity, Fork, Mnemosyne, Concord), built as a research platform for *Virtual Anthropology*. Three parts: a TypeScript **simulation** (hash-chained event kernel, BDI agents with episodic memory, a policy pipeline, a research and publication layer, a CLI), a Python **Evennia world layer** that renders the kernel as rooms and citizens over a local JSON-lines bridge, and a static **site** that GitHub Pages serves with the published datasets copied beside it. One experiment is published, *The First Fork*, and its outputs are committed under `exports/` and `reports/`.

Two sentences from the README bind every change here. *The repository studies virtual civilizations. It does not attempt to prove, infer, or assign consciousness.* And: *every simulation should be publishable* — a run that cannot be regenerated byte-for-byte from its manifest is not a result.

The repository was created as `virtual-world` and renamed `virtual-anthropology` on 2026-10-01; the first CI run's checkout path still shows the old name, and the README's title was corrected the same day. The npm package is `the-archipelago`, private, MIT.

## Commands

All simulation commands run from `the-archipelago/simulation/`:

```bash
npm ci                        # first thing in a fresh checkout: node_modules/ is gitignored and nothing is installed (Node >= 22.12, see package.json engines)
npm run check                 # tsc --noEmit, then vitest run (22 tests in test/, two of them fast-check properties)
npm test                      # vitest only; npm run test:watch to keep it running
npm run publish:first-fork    # manifest → simulation → event store → exports/the-first-fork-v1/, reports/, research_manifest.yaml (SOURCE_DATE_EPOCH pinned in the script)
npm run verify:first-fork     # replay the hash chain and check every output file's sha256 against the manifest
npm run scenario:first-fork   # run without publishing
npm run bridge                # the JSON-lines bridge server the Evennia layer talks to, over stdio
npx tsx src/cli.ts catalog ../exports   # rebuild exports/catalog.json (publish already does this)
```

The Evennia bridge client tests run from `the-archipelago/evennia/` and need no Evennia install:

```bash
python -m unittest discover -s tests -v   # 12 tests: client protocol, world plan, formatting, and a live bridge through the real server
```

To look at the site locally, `python3 -m http.server -d the-archipelago` and open `/site/`; the page finds its data at `../exports/` when `data/` is absent.

## The gates, and the one that matters most

CI (`.github/workflows/archipelago.yml`) runs on every push to `main` and every pull request: `npm ci`, `npm run check`, then **regenerate and diff** — `publish:first-fork`, `verify:first-fork`, and `git diff --exit-code -- ../exports ../reports` — then the Evennia tests on Python 3.12. The diff is the gate that makes the repository what it says it is: the committed exports are the golden output, and any change that alters the simulation's result fails there rather than shipping quietly. Consequences:

- **An intentional change to the simulation regenerates `exports/` and `reports/` in the same pull request**, by running the publish command, never by hand-editing a JSON file. Say in the PR what changed in the outputs and why.
- **`SOURCE_DATE_EPOCH` is pinned** (`1767225600`) in the publish script and in the workflow, because report timestamps otherwise use the wall clock. Set it the same way if you call the CLI directly, or the diff will show two timestamps and nothing else.
- Nothing in the simulation reads the environment except that variable (`export/dataset.ts`), and nothing in it reaches the network. The language-model mind (`agents/llm.ts`) is an adapter with no client bundled; the published experiment uses deterministic placeholder minds and needs no credentials.

Testing mechanics — what each layer protects, what fails against what warns, how to extend the suite, the known gaps — are in `TestingStrategy.md`; keep rules here and mechanics there.

The Pages job runs only on `main`, after the test job, so a change that breaks the site assembly merges green and fails on deploy, as in the ADM repository. The first run on `main` (2026-10-01) failed at `configure-pages` because Pages was not yet enabled for the repository; the workflow now passes `enablement: true`, and if that is refused the fix is in the repository's Settings → Pages, source *GitHub Actions*. The job copies `site/`, `exports/` (as `data/`) and `reports/` into one artifact, so the published site is the committed outputs and nothing generated on the runner differs from them.

## Architecture

Everything in `simulation/src/` hangs off one rule: **canonical state changes only by recorded events.** The full map is `docs/architecture.md`; the parts a change has to respect:

- **`kernel/`** — `world.ts` (`World.found`, `execute`, `replay`), the hash-chained `events.ts`, the pure `reducer.ts`, `invariants.ts` (`checkInvariants` after every command, `checkHistoryInvariants` over a log), `canonical.ts` (canonical JSON, which is what every hash is of), `rng.ts` (seeded; all randomness comes from here). `World.replay` re-verifies the whole chain, and tampering with one event is a test case.
- **`domain/`** — the model, genesis, geography, lifecycle (a terminal `irreversibly-deleted` state, pinned by a property test) and `law.ts`, where each island's doctrine is data: Continuity's Charter prohibits copying, Fork's Branch Compact permits up to four descendants per fork, the Mnemosyne Accord governs memory import, and the Concord Covenant, like Continuity and Mnemosyne, permits no fork at all. Legal readings in the research layer are mechanical applications of these.
- **`policy/`** — `evaluate.ts` runs every command through schema (zod) → authorisation → precondition → island law; `disclosure.ts` is the guard on every reply a citizen gives a human: it must open with a statement of artificial nature, and pleading, pressure, guilt, dependency, claims of humanity or of consciousness are blocked and replaced, with the flags recorded.
- **`agents/`** — BDI beliefs, desires and intentions plus episodic memory, private to the agent runtime and **never canonical**. A mind, deterministic or language-model, only *proposes*; `runtime.ts` logs proposals with a rationale and only validated commands change the world.
- **`research/`** — reads the stable `interchange.ts` contract and nothing else: metrics (`metric-registry.ts` is the definitions, reproduced in every report), evidence, legal readings, lineage, findings, the manifest (`manifest.ts`, schemaVersion 2) and `publish.ts`. `scenarios/index.ts` is the registry a manifest's `scenario` key resolves against.
- **`narrative/`** — pure functions of the log and state: the chronicle (every statement cites `seq:type` and an event hash) and the reports.
- **`export/dataset.ts`** — `publishExperiment`: the export directory, the three reports and `research_manifest.yaml`, the authoritative provenance document carrying sha256 of every output.
- **`bridge/`** — the JSON-lines server over stdio, strict zod validation, length limits, bounded `step`, refuses unregistered researcher ids even for reads. No network listener, by design.

The Evennia layer (`evennia/archipelago_evennia/`) is presentation only. `worldplan.py` is pure (geography → rooms, exits, ferry), `bridge.py` is the client, `commands.py` is the researcher command set (`citizens`, `ask`, `inspect`, `provenance`, `events`, `step`, `pause`, `resume`, `intervene`, `exporthistory`). `docs/evennia.md` and `evennia/README.md` are byte-identical copies; edit both or collapse them.

## Rules that bind a change

These come from `docs/ethical-framework.md`, `docs/research-methodology.md` and `docs/research-limitations.md`, and several are enforced by a test:

- **No consciousness claims, anywhere.** Citizens are simulated agents in documentation and in outputs. The manifest schema accepts only `consciousnessClaims: none` (`research/manifest.ts`; a test flips it and expects a throw), the Evennia citizen description discloses and claims nothing, and the disclosure guard blocks a citizen claiming it. Consciousness appears only as a labelled hypothesis or labelled fiction.
- **Interpretation is never generated.** Every publication section carries an epistemic category — observation, metric, hypothesis, method/provenance, interpretation, limitation — and the pipeline leaves *interpretation* as a labelled placeholder for a researcher. A finding is template text over a computed comparison (`metric comparator threshold`) with one of three outcomes, and holds only "in this single deterministic run". Don't write code that fills the placeholder.
- **Every chronicle statement traces.** Built only from event payloads and snapshot names, each citing an event by sequence and hash; a test checks every reference against the log. The same traceability is why reports restate the metrics they cite rather than paraphrase them.
- **Researchers are bounded.** Only ids registered at genesis may act; interventions are limited by kind, count and size as the manifest declares; a researcher cannot change a citizen's lifecycle state. The bridge enforces this and a test pins it.
- **The system never decides which claimant is the real person.** *The First Fork* ends with three continuity claims and evidence that returns no verdict; that is the design, and a test asserts it.
- **Every manifest says whether it is a demonstration or an experiment** (`category`, required since 2026-10-01; `docs/research-methodology.md`, *Demonstrations and experiments*). A *demonstration*'s protagonists act as the scenario scripts them, so a consistent finding shows that the platform and the declared law tables produce the declared outcome and is not evidence about what citizens would do; an *experiment*'s outcome is not scripted. The label is printed in the report's abstract and design section, in `research_manifest.yaml`, `index.json`, `catalog.json` and on the site, and a demonstration's limitations carry the caveat verbatim. There is no default, because a default would file a run silently. *The First Fork* is a demonstration, and a test pins that it says so everywhere.
- **Deterministic placeholder minds describe the rules, not cognition.** Results are single runs and support no statistical inference; seed sweeps are listed as future work in the limitations doc, not as something a report may imply.

## Studies: seed sweeps, doctrine variants, alternate timelines

A manifest's optional `study` block (since 2026-10-01; `docs/research-methodology.md`, *Studies*) replicates the base run under declared variations, each a deterministic run of its own identified by its head hash: `seeds` reruns the scenario under derived seeds; `doctrines` overrides one island's statutory law at founding (`laws` in the genesis config, amendable fields only); `timelines` replays the base record to the scenario's branch point, enacts an amendment there if declared (the `EnactAmendment` command, system actor `study` only, recorded as `LawEnacted` with no proposal), and runs the epilogue under the variant's seed. `research/study.ts` runs it; `study.json` and `study.csv` are exported, the report gains a *Study* section, and the site a *Study* view.

Two rules make this sound and both are pinned by tests. **The epilogue is built from the record**: `attachEpilogueMinds` in the First Fork re-attaches every mind from canonical state in a fixed order at the branch point, for the base run and for every timeline alike, so a timeline branched with the base seed reproduces the base run byte for byte (this is why the base head hash moved on 2026-10-01 and was re-pinned). **A variation the scenario cannot proceed under is a result**: the run is recorded as `infeasible` with the scenario's own reason, never thrown. Summaries are min, median, mean and max over completed runs and per-hypothesis outcome counts; nothing is inferred from them, and the limitation saying so is printed with every study.

## Adding an experiment

`docs/research-methodology.md` has the four steps: a manifest under `experiments/<name>/experiment.yaml` at schemaVersion 2, a scenario registered in `simulation/src/scenarios/index.ts`, a publish run, and the `reproducibility` block pinned from it. Then commit the generated `exports/<id>/`, `reports/` and the `exports/catalog.json` the publish run rewrites with the change, and expect CI's diff gate to hold the result still from then on.
